## What we are building

A privacy-first document pipeline. A user uploads a PDF, DOCX or TXT document. The system:

1. extracts clean text with character offsets,
2. detects the language,
3. classifies the document type (resume, contract, medical note, email, court case),
4. detects PII with two parallel detectors (regex plus validators, and a transformer NER model), using extra rules chosen by document type,
5. resolves overlapping and conflicting spans,
6. redacts with consistent pseudonyms (the same person always becomes the same placeholder, across mentions like "John Smith", "Mr. Smith", "Smith"),
7. evaluates detection against gold annotations,
8. lets the user chat with the **redacted** document through retrieval-augmented generation on a **local** LLM (Ollama). No document text, redacted or not, is ever sent to an external API.

## Goals, in priority order

1. **A working pipeline** with a clean, typed, tested Python package and a CLI.
2. **Evidence.** Per-PII-type precision, recall and F1, compared against Microsoft Presidio as the baseline. Recall is the headline metric.
3. **Three experiments** whose results go into `reports/`:
   - Privacy vs. utility: answer quality at four redaction levels.
   - Leak test: does LLM output ever contain original PII?
   - Error propagation: oracle ablation of each upstream stage.
4. **A polished Streamlit demo** that a professor can use in two minutes: upload, see highlighted PII, see the redacted version, chat with it, see the metrics.
5. **Report-ready outputs:** figures (PNG + SVG) and tables (CSV + Markdown) generated by scripts, never by hand.

- Tests: unit tests for each module, plus one end-to-end test that runs the full pipeline on a fixture document in under 30 seconds on CPU.
- No notebooks inside `src/`. Notebooks live in `notebooks/` and only call package code.
